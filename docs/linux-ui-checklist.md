# Linux UI checklist

Every user-visible feature of upstream macOS agterm (v0.36.0), with the form it takes in the GTK4/libadwaita build and
a manual check against upstream's behavior. The suite has no Linux UI driver (`tests/ui` skips on Linux), so this list
is how the UI is verified: Task 36 walks it and fixes or records every gap with ⚠️.

Sources, all under `.upstream/agterm`: `site/docs.html` (the user guide), `.claude/rules/*.md` (per-subsystem
contracts), `agterm/Views/*`, `agterm/agtermApp+Menus.swift`, and `conformance/ui-ids.yaml` (the accessibility ids
upstream exposes). The fork's UI (`../agterm-linux`) is only a hint for the GTK form.

How to read it:

- **GTK form**: the widget or idiom standing in for the AppKit/SwiftUI one. Where a control carries one of upstream's
  accessibility ids, the GTK widget's name is that id (`gtk_widget_get_name`), so a future UI driver can find it.
- **Check**: what to do and what upstream does, which the GTK build must match.
- **Built in**: the task that builds it; a later task's number means not built yet at the time of writing. `v0.36
  sync` marks what the v0.35.1 → v0.36.0 upstream sync ported; those rows and parts of rows were read against the
  code once every port of that sync had merged.
- **Walk (Task 36)**: the row read against the code and upstream's sources: ✅ the GTK form exists and matches the
  check as far as the code shows (the hands-on check still wants a desktop session), 🔧 a gap Task 36 fixed, ⚠️ a gap
  or exception recorded and left open, "pending Task N" a feature another task builds. The walk ran before Tasks 26.1,
  34 and 35 merged; their rows were read again against the merged code when Task 36 merged.
- Launch for a walk with `scripts/run-dev.sh` (never by hand while the installed fork runs).
- ⚠️ Across rows: upstream's accessibility ids are set as widget names on the sidebar, the settings, the welcome, the
  title bar's buttons and popover rows, and the zoom and dashboard exit buttons, but not yet on the ask dialog, the
  picker, the dashboard grid, the zoomed terminal, the HTML overlay, the search bar, the palettes or the Ctrl-Tab
  switcher (`conformance/ui-ids.yaml` lists them); they matter once a Linux UI driver exists.
